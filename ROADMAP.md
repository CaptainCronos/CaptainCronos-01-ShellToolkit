# Captain Cronos Shell Toolkit Roadmap

Current milestone: **v1.3.0-beta1 — Framework Complete**

Current version line: **v1.3.0-beta1 — Blackbeard**

The Shell Toolkit has moved from a personal Bash collection into an engineered, installable toolkit with versioning, verification, baseline capture, defaults, storage workflows, asset history, shared libraries, and a GitHub-backed development workflow.

## Package Management Standardization

Status: **Complete**

Debian and Ubuntu package automation now uses semantic package operations backed
by the centralized `apt-get`, `apt-cache`, and `dpkg` capability interfaces.
Nala selection and automated `apt` execution have been removed from active code.

## Network Interface Standardization

Status: **Complete**

Linux network-state automation now uses semantic inspection helpers backed by
the centralized `ip` and `ss` capability interfaces. Active Linux `netstat`
fallback and independent network executable selection have been removed.

## Service Management Standardization

Status: **Complete**

Systemd service, timer, and journal automation now uses explicitly scoped
semantic helpers backed by the centralized `systemctl` and `journalctl`
capability interfaces. OpenRC and FreeBSD rc selection remains platform-scoped.

## Phase 2 — Installer and Command Framework

Status: **Complete for v1.3.0-beta1**

Purpose:

Build the Shell Toolkit into a self-maintaining package-style system with a single command front-end, intelligent installation, verification, and upgrade paths.

### Phase 2.1 — Intelligent Installer

Status: **Complete for v1.3.0-beta1**

Completed goals:

- Support `--help` and `--version`.
- Support `--dry-run`.
- Support `--no-backup`.
- Support `--no-baseline`.
- Support `--no-bashrc`.
- Support `--no-commands`.
- Verify repository structure before install.
- Verify Bash syntax before install.
- Capture baseline when needed.
- Back up existing user shell files.
- Install shell files.
- Install `cc` into `~/bin`.
- Verify installed files after install.

### Phase 2.2 — Unified `cc` Command Framework

Status: **Complete for v1.3.0-beta1**

The command front-end is:

```bash
cc <command> [options]
```

Completed direction:

- `tools/cc` acts as a dispatcher.
- Built-in commands live under `tools/commands/`.
- Help output is generated by scanning command metadata.
- Future plugins can add command directories without modifying the dispatcher.

### Phase 2.3 — Expanded `cc doctor`

Status: **Complete for v1.3.0-beta1**

Completed goals:

- Check repository verification.
- Check Git status.
- Check script syntax.
- Check installed command front-end.
- Check host basics.
- Check reboot marker.
- Check disk pressure.
- Check SMART tooling.
- Support `--full` storage and SMART summaries.
- Print colorized pass/warn/fail status output.

### Phase 2.4 — Manifest-Driven Installation

Status: **Deferred**

Goal:

Move installation source and destination mappings into `manifest.yml` so installer logic is not hardcoded.

This remains a future framework improvement and is not required for the `v1.3.0-beta1` milestone.

### Phase 2.5 — Self-Documentation

Status: **In Progress / Continuing**

Completed:

- Command metadata audit.
- Documentation lint.
- Registry load checks.

Remaining:

- Generate future `docs/user/Commands.md` automatically.
- Keep `helpme`, docs, and command index synchronized through generation.
